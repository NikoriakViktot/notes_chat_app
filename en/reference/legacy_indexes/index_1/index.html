    Key concepts¶

    • IP address — a unique identifier of a computer on the network
    • DNS — translates github.com into 140.82.121.4
    • TCP — guaranteed packet delivery (handshake, sequence numbers)
    • Port — indicates which program the traffic goes to (80→Nginx, 5432→PostgreSQL)
    • HTTP — a text protocol: method + path + headers + body
    • HTTPS — HTTP + TLS encryption
    • Stateless — HTTP does not remember anything between requests → Cookies + Sessions
    • Socket — a bidirectional connection endpoint between programs

    Part 2 — How a request reaches Python¶

    The full path of an HTTP request¶

    Browser
  │
  │ DNS: example.com → 203.0.113.10
  │ TCP + TLS Handshake
  │ HTTP GET /products/
  ▼
Nginx (Reverse Proxy :443)
  │ Static file? → serves it from disk (CSS, JS, PNG)
  │ Dynamic request? → forwarding
  ▼
Gunicorn (Process Manager)
  │ Manages Python workers
  ▼
Uvicorn Worker (ASGI) or uWSGI (WSGI)
  │ HTTP bytes → Python dict (environ)
  ▼
Django Application
  │ Middleware → URL Dispatcher → View → ORM → Template
  ▼
PostgreSQL / Redis
  │ SQL query → data
  ▼
HTTP Response → Gunicorn → Nginx → Browser

    The critical order of commands¶

    # New project
django-admin startproject myproject
python manage.py startapp myapp
# → register it in INSTALLED_APPS

# Development cycle
# (change models.py)
python manage.py makemigrations   # records the plan
python manage.py migrate          # applies it to the DB

# Admin
python manage.py createsuperuser

# Development
python manage.py runserver

# Before deployment
python manage.py check --deploy
python manage.py collectstatic

    Part 5 — Django components¶

    URL Routing¶

    File What it gives you
    Django_URL_Routing.md URL Dispatcher, path converters, GET/POST params, Forms, ModelForms, CreateView

    Key concepts: - Route lookup goes top to bottom and stops at the first match - include() — splits routes into isolated modules - <int:pk>, <str:username> — capture variables from the URL - Static routes must come before dynamic ones

    Views¶

    File What it gives you
    Django_Views.md FBV vs CBV, Generic Views (ListView, DetailView, CreateView), lifecycle

    Key concepts: - A view is the central orchestrator: receives a request → queries the DB → returns a response - FBV (Function-Based Views) — simple, explicit, flexible - CBV (Class-Based Views) — OOP, inheritance, less duplication - Generic Views — ListView, DetailView, CreateView automate CRUD

    Templates (DTL)¶

    File What it gives you
    Django_Templates.md DTL syntax, context system, security (XSS), template inheritance

    Key concepts: - {{ variable }} — outputs variables (with automatic HTML escaping) - {% tag %} — logic: for, if, extends, block, url, csrf_token - {{ var|filter }} — transformation: |date, |truncatewords, |lower - Template inheritance: base.html → child templates via {% extends %}

    ORM and the database¶

    File What it gives you
    Django_ORM.md QuerySet API, the N+1 problem, transactions, MVCC, production pitfalls

    Key concepts: - A QuerySet is lazy: SQL runs only on iteration - select_related — a JOIN at the SQL level (for ForeignKey) - prefetch_related — a separate query + a Python join (for ManyToMany) - The N+1 problem — 1 query for the list + N queries in a loop → disaster - transaction.atomic() — atomic DB operations - MVCC — PostgreSQL keeps row versions for transaction isolation

    Services, Selectors & Serializers¶

    File What it gives you
    DJANGO_SERVICES_SELECTORS.md The business layer: Services (mutations), Selectors (reads), Serializers as a transport boundary
    DJANGO_SERVICES.md Only services.py: stateless functions, transactions, on_commit, side effects, patterns
    DJANGO_SELECTORS.md Only selectors.py: CQRS-light, named queries, N+1, ORM optimizations, patterns
    DJANGO_SERIALIZERS.md Only serializers.py: Input/Output, validate(), fields, a pure Python function, errors
    DJANGO_TASKS.md Only tasks.py: Celery, broker, retry, on_commit, idempotency, patterns

    Key concepts: - services.py — business logic, @transaction.atomic, on_commit for side effects - selectors.py — read-only ORM queries, select_related, prefetch_related, CQRS-light - InputSerializer / OutputSerializer — explicit contracts instead of ModelSerializer - A service knows nothing about HTTP — it is called the same way from a View, Celery or the CLI - N+1 is centralized in the Selector instead of spreading across Views and Tasks

    Key concepts: - makemigrations — generates a Python plan of changes (does not change the DB) - migrate — executes SQL (changes the DB) - Dependency graph — migrations run in the correct order automatically - Migration files — committed to Git together with the code

    Part 6 — Production architecture¶

    Technology stack¶

    Component Role
    Nginx Reverse proxy, SSL, serving static files
    Gunicorn Process manager for Python workers
    Uvicorn ASGI worker with an event loop (async)
    uWSGI WSGI worker (sync, traditional)
    PostgreSQL The main relational database
    Redis Cache, sessions, Celery broker
    Celery Background tasks (email, reports, processing)
    Docker Environment isolation and reproducibility

    WSGI vs ASGI¶

    WSGI ASGI
    Synchronicity Synchronous Asynchronous
    Worker 1 request per worker Thousands of coroutines per worker
    Blocking Yes — waits for the DB No — await frees the worker
    WebSockets No Yes
    Server Gunicorn + uWSGI Uvicorn + Daphne
    When Traditional sites API, real-time, high-load

    Common mistakes — Summary table¶

    Mistake Component Consequence Solution
    N+1 queries ORM Thousands of SQL queries select_related, prefetch_related
    Blocking code in a View Views/WSGI Frozen worker async def view + await
    Logic in Templates Templates Impossible to test Move it into the View or Model
    Auth before Session in Middleware Middleware Empty request.user Correct Middleware order
    runserver in production Deployment Crash under load Gunicorn + Nginx
    No collectstatic Deployment 404 for static files collectstatic + Nginx
    DEBUG=True in production Security Configuration leak DEBUG=False
    Race condition on save() ORM Data loss F() expressions
    atomic() exception trap ORM/DB TransactionManagementError Catch OUTSIDE the atomic block
    Mutable price in Order DB Design Broken financial reporting Store purchase_price in OrderItem
