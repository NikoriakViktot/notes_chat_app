    2. Методологічна база¶

    2.1. Дидактичні принципи¶

    Аналіз базується на класичних дидактичних принципах, сформульованих Яном Амосом Коменським і розвинених у сучасній педагогіці:

    № Принцип Суть
    1 Науковість Зміст відображає сучасний науковий стан галузі
    2 Систематичність і послідовність Теми розташовані у логічному порядку, кожна спирається на попередню
    3 Доступність Матеріал відповідає рівню підготовки аудиторії (ZPD)
    4 Наочність Абстрактні поняття ілюструються схемами, діаграмами, кодом
    5 Зв'язок теорії з практикою Кожна теорема відображається у реальному коді
    6 Активність і свідомість Студент не лише читає, але й виконує завдання
    7 Міцність засвоєння Повторення, контрольні питання, тести
    8 Індивідуалізація Диференціація за рівнями складності
    9 Повнота Охоплення всіх ключових тем дисципліни
    10 Актуальність Відповідність сучасним практикам галузі

    2.2. Таксономія Блума (когнітивні рівні)¶

    6. Оцінювання (Evaluate)  — критичний аналіз, рецензування, судження
5. Синтез (Create)        — проєктування нового, написання коду з нуля
4. Аналіз (Analyze)       — порівняння підходів, виявлення помилок, debugging
3. Застосування (Apply)   — виконання завдань, написання коду за зразком
2. Розуміння (Understand)  — пояснення концепцій, перефразування
1. Знання (Remember)      — відтворення визначень, команд, назв

    2.3. Теорія ZPD (Л. Виготський)¶

    Зона найближчого розвитку — різниця між тим, що студент може зробити самостійно, і тим, що він може зробити за допомоги. Ефективний курс перебуває у ZPD: не надто легко (нудьга) і не надто складно (фрустрація).

    2.4. Scaffolding (Wood, Bruner, 1976)¶

    Методика поступового зняття навчальної підтримки: на ранніх кроках повний код і пояснення → на пізніших кроках лише вимога + очікуваний результат → у Labs повна самостійність.

    2.5. Конструктивізм (Papert, Piaget)¶

    Знання будується через досвід конструювання. Курс реалізує це через наскрізний проєкт (Notes Chat App): студент будує реальну систему, а не вправляється на ізольованих прикладах.

    2.6. SOLO Taxonomy (Biggs, 1982)¶

    Structure of Observed Learning Outcomes — 5 рівнів структурованості відповіді: - Pre-structural → Uni-structural → Multi-structural → Relational → Extended abstract

    3. Критерії оцінювання¶

    3.1. Шкала¶

    Бал Рівень Опис
    5 Відмінно Принцип реалізований повністю, є докази у кількох місцях курсу
    4 Добре Принцип реалізований добре, є незначні прогалини
    3 Задовільно Принцип частково реалізований, є суттєві прогалини
    2 Незадовільно Принцип слабо реалізований, переважають прогалини
    1 Критично Принцип практично відсутній або порушений

    3.2. Критерії¶

    № Критерій Дидактичний принцип Що оцінюється
    К1 Науковість змісту Науковість Точність термінів, відповідність Django 5.2, відсутність застарілих API
    К2 Логічна послідовність Систематичність Чи кожна тема логічно випливає з попередньої
    К3 Доступність викладу Доступність (ZPD) Чи відповідає складність рівню початківця з Python
    К4 Наочність Наочність Кількість і якість діаграм, схем, кодових прикладів
    К5 Зв'язок теорії з практикою Зв'язок теорії з практикою Чи кожна тема прив'язана до реального Notes Chat App
    К6 Активізація діяльності Активність Контрольні питання, практичні завдання, Labs
    К7 Міцність засвоєння Міцність Повторення тем, spiraling, cross-references
    К8 Диференціація Індивідуалізація Маршрути різної тривалості, рівні складності
    К9 Повнота охоплення Повнота Чи охоплені всі необхідні теми Django-розробки
    К10 Актуальність Актуальність Відповідність Django 5.2, Python 3.12, Docker, GitHub Actions 2024

    2. Відсутність студентського зворотного зв'язку: аналіз є внутрішнім — без даних від реальних студентів.
    3. MkDocs build: заблокований (MkDocs не встановлений) — навігаційна валідація не проводилась.
    4. PostgreSQL/Redis/Selenium: тестовий запуск не виконувався під час аналізу.
